# 🖥️ Agent-CI-Lens: User Interface Guide (Model 6.1)

In Agent-CI-Lens, the "User Interface" is a hybrid experience combining structured Markdown files in `agent_context/` and real-time telemetry in the Terminal. This setup governs the communication, memory, and task execution of the autonomous agents.

---

## 1. `TASKS.md` (The Engine's Blueprint)
This is the most critical file. It has transitioned from a simple list to a **Contract-Driven Specification** format based on Karpathy Loop primitives.

### `## [USER_QUEUE]` (Operator Input)
Every goal must now follow the strict triple-structure generated by `make spec`:
- **INTENT**: The technical purpose and business value.
- **CONSTRAINTS**: Strict boundaries (files, libraries, forbidden patterns).
- **METRIC**: Machine-readable success thresholds (e.g., `coverage>=90 complexity<=5`).

### `## [AGENT_PROGRESS]` (Machine Output)
Controlled by the **Queen**. In Model 6.1, these are **Atomic Tasks**.
- Each line represents a Pydantic `AtomicTask`.
- **Atomicity:** A single task now explicitly links logic (`src/`) and testing (`tests/`) to prevent pipeline fragmentation.

---

## 2. `SESSION.md` (Active Work-Session & Bimetric Shield)
This file implements **Bimetric Isolation** to protect human instructions from being corrupted by AI.

### The Bimetric Split:
1.  **`[USER_SECTION]`**: The "Command Deck" (Read-Only for agents).
    - **`[CONTEXT]`**: Where you provide immediate guidance or manual corrections.
2.  **`[AGENT_SECTION]`**: The "Engine Room" (Owned by the Router).
    - **`[STATE]`**: Real-time state indicator (STRATEGY, EXECUTING, LINTING, etc.).
    - **`[FEEDBACK]`**: A smart buffer. Engine v2.0 cleans up transient `LAST_ERROR` lines upon success while preserving persistent `PLANNED` metadata.
    - **`[ACTION_LOG]`**: A chronological record. Automatically pruned by the `context-compressor` when reaching the Yellow Zone (70% context).

---

## 3. `MEMORY.md` (Long-Term Identity)
The "Knowledge Base" for the project's soul. It provides the static context that agents must never forget.

- **Operator Strategy:** Update this file when changing the tech stack or core architectural patterns. It serves as the "Primary Instruction" that overrides any agent's default training.

---

## 4. `TROUBLESHOOTING.md` (ACMI RAG Learning)
The system's "Self-Correction Memory". It acts as a manual fallback for the ACMI RAG system.

- **The `### @` Mechanism:** If an agent repeats a mistake, add a keyword-mapped entry here. The Router will detect the error pattern and inject your specific fix directly into the agent's prompt as a "Critical Hint".

---

## 5. The Terminal (Real-Time Telemetry UI)
The Terminal is no longer just for logs; in Model 6.1, it is a **Financial and Operational Dashboard**.

- **Visual Cues:** Uses emojis to distinguish between stage transitions (🔄), successes (✅), and technical failures (⚠️).
- **Sémantic Logging:** Distinguishes between `Planned` (synthetic goals) and `Finished` (atomic tasks).
- **Telemetry Display:** Commands like `make tokens-last` provide a structured view of costs and model performance, effectively acting as an "Admin UI".

---

## 💡 Operator Strategy Table

| If you want to... | Use this file/command |
| :--- | :--- |
| **Start a new feature** | `make spec TASK="..."` -> `TASKS.md` |
| **Force a specific library** | `MEMORY.md` (Long-term) or `TASKS.md` (Goal-specific) |
| **Fix a persistent Mypy bug** | `TROUBLESHOOTING.md` |
| **Check project costs** | `make tokens-total` |
| **Correct an agent's logic mid-run**| `SESSION.md` -> `[CONTEXT]` |
